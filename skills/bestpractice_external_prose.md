# 外部中文 Prose 诊断词汇表（Manager Reference）

## 元数据

- **类型**：Manager Reference（诊断词汇，不是 gate 清单）
- **适用场景**：Main Agent 在写 `voice_contract.md`、诊断一篇候选为什么端着或认知超载时查阅。
- **使用限制**：只供 Main Agent 阅读。**严禁**整份塞进 prose Writer 的生成上下文，也**不是**验收时逐条打勾的检查表——验收发生在 workflow 的三道 live gate 里，本文件只提供命名和判断依据。
- **最后更新**：2026-07-23

## 0. 这份文件为什么存在，怎么用

`workflow_external_writing.md` 的教训是：把同一条反-textbook 规则写进九个地方、再让模型自述"我扫过了没问题"，规则不会 bind——模型看得见症状（无提示冷读能读出"低亲密度、克制"），但自述式的 verdict 从不把症状转成阻断。所以规则的落点分两层：**workflow spine 里是可执行、能阻断的 gate**；**本文件是 Main Agent 诊断和写 voice_contract 时的词汇表**。同一条原则只在 spine 出现一次；需要展开的"为什么、怎么认"放这里。

不要在正文里把本文件的段落当成"已通过的 gate"来叙述。它不产出 PASS。

## 1. 自然中文不是"满足禁令后的剩余区域"

自然的外部中文，是作者以平等同行的距离，直接向聪明但缺乏本题上下文的读者陈述已核实的发现。它不是把几百条禁令都躲开之后剩下的东西——把整套分类法、历史失败和通篇规则堆给 Writer，只会稀释本题的声音焦点，诱导它用审计和讲义语言组织正文。

Main Agent 的三件事：诊断姿态与架构（为什么端着 / 像讲义 / 认知超载 / 表演式口语化）；据本题证据与真实负例写一页以内的 `voice_contract.md`；冷读时按通读体验判整体声线，而非数禁词。

## 2. 教材声：一个定义，两个方向的偏离

**教材声**（canonical 负例）：全文保持"我已经知道完整地图，现在带你逐项走一遍"的姿态。典型节奏是**宣布主题 → 下定义 → 解释机制 → 界定边界 → 抽象总结**连续循环。它把读者当受训对象。注意：删掉"首先/其次/第三"、把编号改成"一个边界、另一个边界"**不改变**这个姿态——结构没变，只是措辞变了。这是最常被误判为"已修好"的地方。

三个偏离方向：
- **教材声**：如上。像课程讲义。
- **表演式口语**：滥用俚语、夸张比喻、假对话、过多第二人称，用形式亲切掩盖机制没讲清。
- **极性夸张与情绪化定性**：滥用绝对化否定与戏剧化强修饰（如“这根本不是……”、“绝不取决于……”、“绝不意味着……”、“印证了一个残酷现实”、“根本无法杜绝”、“极其典型”、“死死锁在……”、“极端的战略阳谋”）。这会让文章带有情绪倾向或戏剧化炒作感，损害专业同伴式的中立、客观与克制。**诊断改法**：去掉极性修饰词与绝对化句式（如将“印证了一个残酷现实”改为“印证了一个现实”，将“根本无法杜绝”改为“无法杜绝”，将“绝不意味着”改为“并不意味着”，将“极其典型的案例”改为“典型的案例”），不用双引号包裹普通概念词，用具体事实、数据和利益边界自然引出结论。

**正向姿态**：作者和读者面对同一个具体对象，沿动作、限制、后果推进；概念按需出现，判断落在证据之后；入口直接从本篇特有的新事实或冲突进入；段落停在观察到的后果或未决问题上，不强加宏大总结。贯穿全文的具体场景和运行示例必须严格基于 `source_contract.md` 或明确标注为假想——绝不靠虚构现场事故、推测的用户反应或未受支持的因果来制造"自然"。

## 3. 亲切来自认识运动，不来自口语装饰

实践者文章最自然的推进不是"我知道什么"，而是"我原来怎样理解、遇到了什么、哪个动作让判断改变"。这类**认识运动**可以来自真实尝试、失败、取舍或一个明确的反事实检查，不要求表演情绪，也不要求每段第一人称。

诊断关键：不要把"专业同伴式、克制、结构清楚"自动当作声线通过。若陌生读者把作者识别为**替自己整理知识的讲师 / 顾问 / 规范制定者**，而不是**正在分享一个具体发现的实践者**，即使全文没有官话，也是叙述距离过远。`低亲密度`、`工程实践指南`、`系统性倡议`、`压缩判断成本` 这些无提示文体判断都是重读信号，不是正面评价。正向信号是：读者能回答"作者以前怎么做、为什么一度觉得够用、后来观察到什么、最终改了哪个判断"。只展示完成态知识与最佳实践，通常仍是教材声。

## 4. 认知负荷：诊断词汇

声线失败常源于按**作者的知识地图**组织文章，而不是按**读者的理解过程**组织。

**认知舒适度**：即使每个专有名词都单独解释过，若一段强迫读者同时维护过多未落地的分类、比较轴或系统组件，仍是超载。信号——读者必须停下、向前翻查或手动画关系才能跟上。解释一个术语不消除它的认知成本：读者第一次遇到工具名/组件/机制/边界时，要同时记住"它是什么、此刻在做什么、与前一个概念什么关系"。一句语法清楚的话仍可能一次塞进五六个前置概念（"borg check 不能替代真实提取"就是一例：短短一句里叠了归档、校验、恢复、可提取性等多个前置概念）。

**读者概念账本**（认知走查的方法）：按自然段维护三项——本段新增的陌生概念、已由具体动作落地的概念、跨段仍悬空的关系。高风险信号（不是可机械刷分的充分条件）：一段引入两个以上陌生概念；跨段仍需维护四个以上未落地的关系；读者只能照抄术语、不能用普通语言复述；抽象概念出现前没有人/文件/请求/设备发生对应动作；删掉专有名词后读者说不出这段改变了什么。最重要的验收是**逐节复述**：只依据已读到的正文，目标读者能否不用新术语回答"刚才发生了什么、为什么旧办法不够、下一步为什么自然出现"。答不出时减少概念或补具体例子，不要继续追加定义。

**概念预算与主动舍弃**：`source_contract.md` 是允许使用的事实边界，**不是正文 coverage checklist**。区分三类：读者理解 thesis 必需的概念、只对实现者有用的细节、仅防事实越界的材料——后两类进附件/prompt/脚注或直接省略。低认知负担常来自主动不讲：删掉一个平台边界或组件说明后普通读者仍懂核心判断，它就不该只因"研究过了"留在正文。

**过度压缩不是低负担（另一端的失败）**：把文章压成"机构名 + 一句定性""法域名 + 一句差异""建议 + 一句 checklist"，事实全对，读者却没经历旧安排→具体动作→新后果的因果链。Low Cognitive Burden 与文章长度正交：低负荷指的是容易理解、因果连贯与段落呼吸感，绝不等于压缩篇幅或砍掉必要的上下文细节。若把段落切成连续的说明书短句，反而会让读者悬空概念、增加解码负荷。低负担不是删解释，是让读者任一时刻只需理解一个正在变化的对象。若每段压成一句后几乎没有信息损失，稿件只是正确提纲。

## 5. 段落架构：诊断信号

- **概念依赖顺序**：先展示真实痛点与动作（系统何时卡住 → 采取什么操作 → 产生什么改变），概念在解决问题时落地；避免"先抽象定义，再讲使用"。
- **局部地图**：读者确需比较三个及以上有限替代方案时，展开前先给选项总数与统一比较基准。不要把所有结构化比较机械判为教材声；缺局部地图的连续展开同样损害舒适度。
- **章节衔接**：遮住相邻 H2，连读前节结尾与后节开头。自然衔接由同一对象的下一动作、新暴露的边界或前一选择的后果驱动；只能靠标题补因果，说明交接要重写。
- **模式词是诊断信号不是禁词**："这是一个…""要理解 X 必须先理解 Y""这意味着深远影响"是定义式入口/抽象主语/总结尾巴的信号。发现后重构段落推进，而不是做同义词替换。
- **括号补译不是术语解释**："可观测能力（observability）""provenance（来源链）"这类双写通常只证明作者认识英文词，没帮读者理解它在当前动作里的作用。除正式全称、缩写展开、原文引语或确有检索价值的首次名称外，不用"中文（English）"或"English（中文释义）"。选一个正文称呼，让后续动作解释它。删掉括号内容后意义不变就直接删；删后无法理解，说明句法没承担解释职责，要重写关系而非保留词条。
- **分析框架必须先熔融**：时间线、两轴、三层、四问、六项 checklist 帮 Main Agent 思考，但不能自动同时变成 H2、图片、列表和结尾。做 **scaffold deletion test**：删掉"两轴/三层/四问"标签，具体对象、动作、后果还能推动全文吗？不能，说明没有叙述骨架；能，就只保留真正降负担的那一处显式框架。

## 6. 两个专项诊断（新增词汇，非 gate）

- **承重区分的因果自洽（load-bearing distinction）**：当 thesis 建立在一个"二分"上（两份拷贝 / 两种用途 / 并行 vs 顺序），要能重建底层机制、确认这个区分是真实拓扑而非修辞便利的假二分。事实逐条与来源一致，不代表中心区分成立——例如"训练拷贝 vs 磁盘拷贝互斥"逐条可溯源却自相矛盾（训练本身需要保留文件），只有还原流水线的领域读者能识破。source-fidelity 检查过不了这一关。
- **比较的组织单元**：一节若在多个对象上比较共同属性，组织单元应是**属性（一张固定矩阵）**，不是**对象**。逐对象各写一段（FrugalGPT 一段、RouteLLM 一段…）会让读者自己在脑中建矩阵。发现 per-item 枚举，重组为 per-dimension 矩阵（如 scope / signal / output 三维），而不是笼统"降低负担"。

## 7. 怎样写本题 Voice Contract

`voice_contract.md` 控制在一页左右，只含本题所需的正负证据：

- **正向摘录**：1-2 段用户明确认可、解释难度相近的真实段落，注明要学的推进节奏，别引导 Writer 机械套句式。
- **负向摘录**：直接截取**当前 draft** 里最典型的 2-3 段病态段落，点明入口/推进/收尾的具体问题。真实负例远胜通用禁词表。
- **认识运动**：写清本文应让读者看到哪一次真实的旧判断→触发→取舍→新判断。不要只写"亲切、自然、实践者口吻"。
- **读者基线**：只写与声线直接相关的已知/未知边界；完整概念账本放 `audience_contract.md`。

```markdown
# Voice Target
[2-3 句：谁向谁解释什么，叙述姿态与距离]

## Positive Excerpts
[1-2 段真实优质段落]
- 学习重点：[要吸收的段落推进/叙述节奏]

## Current-Draft Hazards
[当前 draft 里 2-3 段典型失败段落]
- 问题诊断：[定义式入口 / 表演式比喻 / 抽象总结尾巴 / 术语堆叠]

## Boundaries & Constraints
- 第一人称与问句边界；技术密度与解释深度限制；局部地图与有限集合比较规范。
- 术语规则：选中文或英文正文称呼，禁止词典式括号补译。
- [不超过 8 条高影响本题约束]
```

## 8. 审稿模型校准（供 spine 的 live gate 引用）

文风判断不能只靠抽象 rubric。给任何 voice/burden 审稿模型一段用户明确认可的正例、一段已确认的教材声负例，先让它解释两者在"作者与读者关系、认识运动、段落言语动作"上的差别；**不能稳定区分校准样本时，它对当前候选的 verdict 作废**。校准不是让 Writer 仿写词句，也不是把正例全文塞进生成上下文——它检验审稿模型是否真懂目标文风，而不是只会数禁词。

把用户反复出现的两条轴——**教材声、认知负荷**——当作常驻的一等 gate 目标，不要每次从零重新猜测反馈会是什么。（"能清楚说出失败在哪"不等于"猜中了用户的具体判断轴"：模型能生成一堆合理的失败假设，仍可能错过用户真正在意的那条。）
