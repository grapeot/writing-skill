# Twitter 导流文案写作工作流（twitter_post_writing）

## 元数据

- **类型**：Workflow（external writing 的渠道子工作流）
- **适用场景**：从一篇已通过双重 gate 的文章生成 Twitter 导流文案（Typefully long post，中文）。发布动作本身（创建 draft、schedule）归发布层 skill，不在本文件内。
- **上游**：`workflow_external_writing.md`（文章层工作流与 gate 哲学）。
- **创建**：2026-08-21。根因依据：对一批已发布文案的实测审计（模板收敛 19/20、格言密度 4-7 条均、事实漂移三项均有量化证据）。
- **执行者**：调用方 agent 编排；两次生成走 `agy --print`（Antigravity CLI，独立上下文），机械检查走 lint CLI 与确定性命令。

## 0. 这个工作流解决什么

历史文案不是"写得差"，是三个系统性问题（2026-08 对 20 条文案的实测）：

1. **模板收敛**：19/20 复用同一骨架（反差/数字 hook → 事实包 → 认知反转 → 数量框架 → 格言收束 → URL）。单条看成立，连读就是同一台论证机器换材料。
2. **格言密度过高**：平均每条 4-7 个"金句式判断单元"，几乎每段一个；结尾 75% 落在可截图的对仗警句上。人写文案让一句金句承担主轴，其余句子负责观察和限定。
3. **事实强度漂移**：文案环节独立引入"16 倍"（不可比口径相除）、"人次"改"场次"、"负 1.1%"改"年年在涨"——压缩时删掉限定词，断言比文章强。

因此：文案不是文章的压缩版，是**一次独立的、有自己 gate 的写作**。

## 1. 工作流总览

```
文章 MD ──→ Stage 1（AGY 独立上下文：提炼认识运动 + 平实初稿）
        └─→ Stage 2（AGY 另一个独立上下文：只读初稿，整篇重写为长推文，含轮换指令）
             └─→ Gate A（机械：lint 适用子集 + tweet 特有检查，必须清零）
             └─→ Gate B（事实保真：数字/量词/限定词逐项对照文章）
                  └─→ tweet_final.md（交付给发布流程）
```

两次 AGY 调用互相看不到对方上下文，也**都不看旧文案**（防止锚定）。文章只进 Stage 1；Stage 2 只读 Stage 1 的产物，这是防止文章里的金句层被直接抽走的关键隔离。

## 2. Stage 1：提炼初稿（prompt 要点）

独立 `agy --print` 调用（`gemini-3.7-flash-high`，`--print-timeout 10m`，scratch 目录内执行）。Prompt 核心（中文，可直接使用）：

> 你是一个善于捕捉认识运动的实践者同行。读下面这篇文章，写一条推文初稿。
> 1. 找认识运动：作者（或读者）原先以为什么 → 看到什么具体证据 → 判断改在哪。文章没有这层素材时，退化为"这套机制解决什么具体痛点用例"，并如实说明没有现成答案的部分。
> 2. 用同行分享发现的姿态平实叙述；不用讲师口吻，不替读者总结方法论。这是新闻/分析类文风：**不用第一人称**，判断转变用无主语叙述承载（"起初容易以为……""翻开报价单才发现……"）。口吻目标是"像跟同事聊天讲一个刚发现的东西"：允许轻微口语连接词（"说白了"这类），句子长短有呼吸。亲切感来自节奏和具体细节，不来自人称、俚语、感叹和比喻装饰。
> 3. 认知负荷预算：全篇只讲一条线（一个判断的转变或一个对象的命运），一条带走点。初稿阶段就做筛选：只保留这条线上的承重事实；与主线无关的数字、公司、机制即使文章里有也不进初稿。宁讲透一件事，不罗列五件事。
> 4. 事实绝对保真：数字、量词（人次/场次/台/席）、限定词原样保留；禁止自行计算倍数或比率；禁止把单案例推成普遍规律。
> 5. 禁用：唯一/恰恰/绝不/才是真正的/根本；"不是A而是B"句式；排比与对仗；任何金句、口号、行动指令。
> 6. 输出 300-600 字，结尾落在一个具体现象、数字或未决问题上。文章全文：<文章内容>

初稿可以超长（保留完整事实骨架），压缩是 Stage 2 的事。

## 3. Stage 2：整篇重写 + 轮换指令（prompt 要点）

另一个独立 `agy --print` 调用，只读 Stage 1 初稿。Prompt 核心：

> 你负责把这份推文草稿整篇重写为可发布的 Typefully long post。你没看过原文，只能基于草稿，不得补任何草稿没有的事实。
> 发布硬约束：300-800 字；无任何 Markdown 标题；全篇唯一 URL 在最后一行（正文提外部来源只写名字，禁止任何裸域名）。
> 文风：像在聊天工具里跟同事讲一件刚发现的事——平实但有对话感。这是新闻/分析类文风：**不用第一人称**，发现过程用无主语叙述（"起初容易以为是人群习惯问题，翻了报价单才发现是账本结构"）。允许轻微口语连接词，句子长短错落。禁止用装饰制造亲切：俚语表演、感叹号轰炸、比喻堆砌、套近乎都算失败；禁止"我"作为叙述主语。亲切来自节奏和具体细节，不来自人称。金句式判断全篇最多 1 个且不得出现在结尾；禁止排比、对仗、祈使句收尾、"一句话带走"式总结。
> 认知负荷约束（读者随时只跟踪一个变化中的对象）：全篇一条线、一个带走点；每段只干一件事（一个对象/一个动作/一个后果），不并置多组比较轴；数字 token 总数 ≤6（年份金额百分比都算），只留承重的，装饰性精确（连串小数点、次要年份）删掉；点名对象（公司/产品/项目名）≤4；一句里不叠两个以上新概念，缩写和代号不进正文。删减时用 Gate B 保住留下的数字的口径。
> 本次指定开头模式：{opener}；本次指定收尾模式：{ending}。

**开头/收尾模式池（防新模板收敛的轮换表）**——按发布序号轮换（`i` 为该渠道第 i 条文案）：

- 开头 `i mod 5`：0 原始问题/困惑；1 白描场景或具体对象；2 单个数字事实直陈（不加反差结构）；3 文章中一处具体细节/引文；4 从边界或例外切入。
- 收尾 `(i+2) mod 5`：0 停在具体事实；1 停在未决问题；2 停在文章原句引用；3 停在适用边界/反例；4 停在下一步观察（陈述式，非祈使）。

禁止把某个模式（如"戛然而止停在现象"）定成唯一合法收尾——那只是把旧模板换成新模板。

## 4. Gate A：机械检查（必须全部清零）

```bash
python -m writing_skill.external_prose_lint_cli tweet_final.md --json
```

lint 结果的适用映射（其余规则如 `h2_count`、`embedded_links`、`title_book_marks` 对推文无意义，忽略）。注意这些 gate 不限制温度：轻口语连接词、语气的长短呼吸都不在扫描范围里，被拦的是表演模式（对仗、极性、元评论、翻译腔）。"亲切自然"与 gate 清零不冲突，冲突的只是用装饰制造亲切。新闻/分析类文风不用第一人称（见 §2/§3），这本身也可机械自查（直接引语中的"我"除外）：

| 规则 | 判定 |
|---|---|
| `em_dash` / `eval_label` / `polarity` / `meta_preamble` / `not_x_but_y` / `when_clause` / `banned_word` / `bracket_gloss` | HARD，必须为 0 |
| `quotes` / `bei_passive` / `single_sentence_paragraph` | REVIEW，逐条给保留理由（推文允许短段，但连续单句段 ≥4 要合并） |
| `bare_url` | 特殊：全篇恰好 1 个且在最后一行，必须是本文的 tracked 分发 URL（自有站点域名 + UTM，具体域名由发布层 overlay 提供）；否则阻断 |

tweet 特有补充检查（确定性，不依赖 lint）：

```bash
grep -c '^#' tweet_final.md          # 必须为 0（无标题）
grep -cE 'https?://' tweet_final.md  # 必须为 1
grep -cE '[a-zA-Z0-9.-]+\.(com|net|org|ai|dev|io)' tweet_final.md  # URL 行以外的裸域名必须为 0
sed '$d' tweet_final.md | grep -oE '[0-9][0-9.,]*%?' | wc -l       # 数字 token 数 ≤6（认知负荷预算，URL 行除外）
```

调用方 agent 只允许做机械级修正（破折号换冒号、删多余引号），修完重跑；需要语义改动就打回 Stage 2 重跑，不许自己凭语感改稿。

## 5. Gate B：事实保真（对照文章）

1. **数字与量词机械核对**：提取文案全部数字、百分比、倍数、量词，逐个在文章全文中检索。文案出现文章没有的数字（含自行计算的倍数/比率）、量词口径改变（人次→场次）→ 阻断，打回 Stage 1。
2. **限定词核对**：文案每个强断言回到文章对应段落，检查限定词（"部分场景""目前"）是否丢失、单案例是否被推成普遍规律。发现漂移 → 阻断。

Gate B 在看不到两个生成阶段的上下文里做（调用方 agent 或第三次独立调用均可，但必须逐项贴出对照结果，禁止自述"核对过了"）。

## 6. 验收标准

一个没参与生成的 agent 只看产物应能判定：

1. Gate A 全部清零，lint stdout 与补充检查输出已落盘；
2. Gate B 逐项对照表已落盘，零漂移；
3. 金句式判断 ≤1 个且不在结尾；无排比对仗收尾；
4. 开头/收尾模式与轮换表指定一致；
5. 末行唯一 tracked 分发 URL（自有站点域名 + UTM，slug 正确）；
6. 300-800 字，无 Markdown 标题；
7. 无第一人称叙述主语：`grep -c 我` 为 0（或仅有的命中全部在直接引语内，逐个说明）；
8. 认知负荷：数字 token ≤6（URL 行除外），点名对象 ≤4，逐段各司一职（复核者按"每段只干一件事"过一遍并在 notes 里确认）。

自然语言"检查过了没问题"而无命令输出 → 定义为 gate 失败（与文章层同一条铁律）。

## 7. 已知陷阱（均实际发生过）

| 陷阱 | 表现 | 应对 |
|---|---|---|
| 金句最大化抽取 | 文案专挑文章最对称、最绝对的句子，删证据留判词 | Stage 2 隔离（不看文章）+ 金句预算 ≤1 |
| 反模板变成新模板 | 禁掉格言收束后，20 条全部"停在现象"又收敛 | 开头/收尾模式池轮换，禁止单一合法模式 |
| 压缩制造数字漂移 | "16 倍""人次→场次""年年上涨" | Gate B 数字逐个回文章检索，倍数必须原文已有 |
| 文章本身无认识运动 | Stage 1 硬找心路历程会幻觉 | 显式退化路径：改讲具体痛点用例，金句禁令不解除 |
| Stage 2 脑补前提 | 隔离后为连贯自行补事实 | 初稿不限长保留事实骨架；Stage 2 prompt 明令"不得补草稿没有的事实"，Gate B 兜底 |
| 亲切被做成装饰 | 要求亲切文风后，模型转而堆俚语、感叹、比喻、套近乎 | prompt 里把亲切操作化为"无主语发现叙述 + 轻口语连接词 + 句子呼吸"，装饰清单列为失败态 |
| 亲切被误操作为第一人称 | 模型把"有对话感"理解为加"我起初/我以为"，与新闻/分析类文风冲突 | prompt 明令禁止"我"作叙述主语；判断转变改用无主语句式承载（实测可行） |
| 降负荷做成信息扫地出门 | 要求一条线后，把文章的承重证据也删光，文案变空泛 | 预算只限数字 token 和点名对象，不限承重事实；主线上的关键证据必须留一个最具体的载体（实测：#20 只留 6 个数字仍讲得透账本结构） |
| agy 并行会话串线 | 同机同时跑多个 `agy --print` 时，会话可能串到无关旧会话或把"当前目录"解析到别的 session 目录，读错 prompt、写错文件 | 同一 scratch 目录内 agy 调用串行执行；prompt 一律用绝对路径；产出文件落盘后先验证非空且内容对题再过 gate |

## 8. 输出规格

`tweet_final.md`：首行即对外正文，末行 URL，无任何内部标注。同目录保留 `stage1_draft.md`、两阶段 prompt 文件、lint/核对 stdout，供审计与失败重跑。
