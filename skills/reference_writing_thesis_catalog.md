## Thesis Catalog：L1 - L8 分析视角

以下视角为作者已发表文章中归纳出的分析习惯。将其当作灵感库，在读者可见的最终成品中不要出现任何 L 编号或视角代号。

### L1: 反馈闭环判断
一个系统的能力天花板取决于它能否感知自身输出并自我修正。最关键的是模型能否看到自己行为的后果并自我迭代（如 Generation 3 绘图利用截图闭环、Agent 代码运行结果反馈）。开环控制走向失控，闭环控制实现可靠。
*(对应 axioms: A02 放大器、A04 可靠性、M01 闭环校准)*

### L2: 成本结构经济学重建
当某项资源成本发生数量级变化（如代码生产、token 挥霍成本趋零）时，系统性对比新旧经济学：旧的最优策略（如 DRY 原则、直觉决策、防御性代码）在旧成本下为何合理，而新成本下的最优策略（如用完即焚、挥霍 token 换取确定性、积累 context 基础设施）又为何发生了颠覆。
*(对应 axioms: X03 瓶颈决定效率、T05 认知是资产/代码是消耗品)*

### L3: 共识天花板判断
LLM 的默认输出是共识（consensus），其安全对齐和概率生成机制决定了它回归均值。真正的差异化和深度只能通过注入非共识的个人上下文（context）来实现，依靠的是 Wide Research 而非一味升级模型。
*(对应 axioms: A10 熟悉度胜过原始智能、Context infrastructure 核心论点)*

### L4: 技术族谱追溯
任何技术发布都不是凭空出现的。追溯其 2-4 代演化轨迹（每代解决的核心问题与留下的局限），定位该事件在演化线上的真实位置，厘清它是“真正的新东西”还是“已有路径的产品化”，并推演下一代的走向。
*(对应 axioms: M06 连接胜过孤立、A13 技术采用三阶段)*

### L5: 表层诊断与底层机制
媒体或厂商的表层叙事（“AI 能做设计”、“AI 偷懒了”）往往掩盖了底层的技术机制和约束条件。文章要逆向重定向读者的注意力，揭示真正驱动结果的底层技术逻辑，从机制上推深一层，而非停留在拟人化的感性描述上。
*(对应 axioms: T04 数据优于观点、V02 可验证性)*

### L6: 执行摩擦消除后的价值重分配
当工具消除了执行层面的摩擦，竞争优势从“谁执行得快”转移到“谁的判断更好”。工具自身价值下降，品味和方向感的价值上升。具体表现为人类角色的重定位：从 IC 转向 Manager、从 User 转向 Builder、从单纯的执行者转变为定义问题与把关结果的“出题人”。
*(对应 axioms: T05 认知是资产、A02 放大器)*

### L7: 管理框架平移
AI 在工程和协作中暴露的不可靠、幻觉、偷懒、沟通成本，本质上在人类组织管理中早有对应（如“新人管理”）。无需发明玄学概念，可直接平移成熟的管理框架（招聘、委托、情境领导力、流程验收和层级化扩展等）来约束和编排 AI。
*(对应 axioms: A03 IC→Manager、A04 可靠性是管理问题)*

### L8: 上下文与信息架构
LLM 系统的故障模式与能力边界，根源在于其 context window 里的信息架构：能看到什么、信息是否整洁、角色是否隔离。设计或诊断系统时，必须先厘清其信息基础（L8），再评估其感知反馈机制（L1），实现激进的反馈透明。
*(对应 axioms: M01 闭环校准、Context infrastructure 核心论点)*
